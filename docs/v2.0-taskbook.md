# V2.0 产品任务书

本文档作为 V2.0 产品分支的主任务书，用于承接 V1.0 后已经明确的新功能目标、页面改版方向和多端产品形态规划。

V1.x 修复分支继续使用 `docs/v1.0-tofix.md`。V2.0 任务不应混入 V1.x bug 修复，除非该修复是 V2 实施的前置依赖。

## 版本定位

V2.0 的目标是把 FMO Dashboard 从“实时仪表盘 + 日志增强工具”升级为更完整的 **FMO 移动控制台和多场景显示屏**。

核心主线：

- 看得清：打开后第一屏直接看到当前通联现场；
- 连得上：局域网、DDNS、内网穿透、App 和便携版都有清楚连接路径；
- 控得动：中继切换、FMO 控制、消息、日志、好友等高频入口前置；
- 找得到人：好友、老朋友、最近通联和提醒能力逐步增强；
- 多端适配：网页版 / iPad、手机 App、车机横屏不再只是同一页面拉伸。

## 版本边界

### V2.0 建议纳入

- 新版仪表盘信息架构；
- 网页版 / iPad、手机竖屏、车机横屏三套布局基础；
- 当前呼叫 + 上一个呼号的现场展示；
- 高频功能入口前置；
- “更多”页面精简；
- 基础中英文切换框架；
- 本地收藏中继 / 常用入口的第一版；
- 远程地址 / DDNS 用户提示的正式化整理。

### V2.0 建议暂不承诺

- 依赖 FMO 固件新增接口的能力；
- 好友关系双向同步；
- 设备间互拉、远程收藏同步；
- 完整自定义主题系统；
- 完整云服务或账号体系；
- 自动化远程访问服务创建。

## 共同设计约束

- 参考切片：`docs/dashboard-redesign-slices.html`；
- 中文产品名统一为 `FMO 仪表盘`；
- 英文产品名统一为 `FMO- Dashboard`；
- 第一屏优先展示当前通联现场，不把历史统计放在主要视觉中心；
- 高频操作要可触达，避免藏在深层“更多”页面；
- 所有端都必须保留当前 FMO 地址、连接状态、当前中继 / 服务器和刷新状态的可见反馈；
- 车机版和移动端必须避免按钮、表格、文字交错和横向溢出；
- 新增业务逻辑优先放在 store 或 core，`src/services/messageService.js` 和 `src/services/gridService.js` 继续保持 facade 定位；
- 大版式改造前，先确认 V1.x 功能 bug 不被新版 UI 掩盖。

## 产品线 A：网页版 / iPad 版

### 定位

网页版 / iPad 版是信息密度最高的主控制台，适合桌面浏览器、iPad 横竖屏和公网 VPS 页面访问。

### V2.0 目标

- 第一屏完成“当前通联现场 + 上个通联 + 最近通联 + 高频入口”的重组；
- 当前呼叫作为第一视觉中心，展示呼号、QTH、网格、距离、方位、当前中继；
- 上一个呼号使用同类信息结构，但视觉权重低于当前呼叫；
- 最近通联列表保留较高信息密度，支持快速查看呼号、时间、QTH、留言、模式、中继；
- 将日志、老朋友、排行榜、消息、设置、FMO 控制、愿望墙、更多等入口前置；
- VPS 网页版补充 HTTP / HTTPS、`ws://` / `wss://`、DDNS 和浏览器安全限制说明；
- iPad 上优先保证横屏布局可用，竖屏沿用移动端密度但保留更多入口。

### 任务拆分

1. 信息架构重排
   - 当前呼叫卡片；
   - 上一个呼号卡片；
   - 最近通联区域；
   - 当前连接 / 当前中继状态条；
   - 高频入口区。
2. 入口前置
   - 日志；
   - 老朋友；
   - 排行榜；
   - 消息；
   - 设置；
   - FMO 控制；
   - 愿望墙；
   - 连接诊断 / 远程地址说明。
3. Web / iPad 响应式
   - 桌面宽屏；
   - iPad 横屏；
   - iPad 竖屏；
   - 公网 VPS 页面。
4. 远程访问说明
   - HTTP 入口用于普通 `ws://` FMO；
   - HTTPS 入口用于支持 `wss://` 的地址；
   - 浏览器自动升级 HTTPS 时的提示；
   - DDNS、反向代理、内网穿透地址保存后的连接反馈。

### 验收要点

- 1366px 桌面、1024px iPad 横屏、768px iPad 竖屏均无横向溢出；
- 第一屏可直接判断当前是否有人发言、正在使用哪个中继、连接是否正常；
- 高频入口不依赖进入“更多”页面；
- VPS HTTPS 下连接普通 `ws://` 失败时，提示能解释浏览器限制。

## 产品线 B：移动端 App（Android / iOS）

### 定位

移动端是随身控制台，重点服务手机竖屏、户外、值守、远程连接和移动网络使用。

### V2.0 目标

- 手机竖屏第一屏优先展示当前呼叫、上个通联、连接状态和核心操作；
- 底部导航清晰，减少“更多”页面深层查找；
- Android 与 iOS 使用同一套页面结构，但保留平台差异处理；
- 地址添加支持 `fmo.local`、局域网 IP、裸 DDNS、`域名:端口`、完整 URL；
- 通联音频、呼号播报、静音开关、系统音频会话和内置音频兜底继续作为移动端重点；
- 愿望墙 / 定位类能力按平台能力区分展示。

### 任务拆分

1. 手机竖屏新版仪表盘
   - 顶部连接状态与设置；
   - 当前呼叫；
   - 上个通联；
   - 最近通联列表；
   - 底部导航。
2. 移动端高频操作
   - 刷新；
   - FMO 控制；
   - 消息；
   - 日志；
   - 设置；
   - 定位 / 愿望墙入口按平台能力显示。
3. Android 专项
   - HarmonyOS 4.0 / Android 10 兼容；
   - 启动阶段原生插件初始化保护；
   - WebView 版本和 API 29 回归测试；
   - 日志页和仪表盘小屏布局回归。
4. iOS 专项
   - 静音开关下通联音频和呼号播报；
   - 内置呼号音频兜底；
   - 设置页横向撑开回归；
   - DDNS 地址保存和连接提示；
   - TestFlight 构建验证。
5. 移动端连接体验
   - 保存地址不因前置探测失败被阻断；
   - 连接失败时区分格式错误、网络不可达、浏览器 / 系统限制；
   - 多地址 / 多入口为 V2.1 预留。

### 验收要点

- 390px、430px、480px 宽度下无横向滚动；
- 当前呼叫、上个通联和连接状态在第一屏可见；
- Android / iOS 地址保存规则与 `src/utils/urlUtils.js` 一致；
- iOS 真机验证静音开关、通联音频、呼号播报；
- HarmonyOS 老机型至少能通过日志定位启动闪退根因，优先避免单个插件失败导致整 App 崩溃。

## 产品线 C：车机版

### 定位

车机版是横屏高对比显示和轻触控场景，目标是在车内快速扫读，不做复杂表单操作。

### V2.0 目标

- 横屏布局独立设计，不简单拉宽手机页面；
- 当前呼叫和上个通联并列展示；
- 当前中继、连接状态、刷新状态始终可见；
- 收藏中继 / 常用入口可横向或纵向滚动；
- 最近通联使用底部横向通栏表格；
- 大字号、高对比、按钮尺寸适合车载触控；
- 尽量减少复杂设置表单在车机第一屏出现。

### 任务拆分

1. 车机横屏基础布局
   - 当前呼叫主卡；
   - 上个通联副卡；
   - 当前中继 / 连接状态；
   - 收藏中继区域；
   - 底部最近通联表格。
2. 车机高对比主题
   - 字号；
   - 密度；
   - 按钮尺寸；
   - 暗色高对比；
   - 强光 / 夜间可读性。
3. 车机交互限制
   - 高频按钮保留；
   - 复杂表单后移；
   - 触控目标尺寸稳定；
   - 横向溢出禁止。
4. 车机入口策略
   - FMO 控制；
   - 收藏中继；
   - 最近通联；
   - 消息可作为低层级入口；
   - 设置只保留必要项。

### 验收要点

- 1280x720、1366x768、1920x1080 横屏无交错和横向溢出；
- 当前呼叫和上个通联能在驾驶扫读场景下快速识别；
- 收藏中继区域可滚动但不挤压主通联信息；
- 最近通联底部表格不遮挡主卡片。

## 横向能力：中英文切换

### V2.0 目标

- 所有页面右上角设置齿轮右侧增加地球图标；
- 点击地球图标切换中文 / English；
- 先覆盖核心页面和导航，不追求一次翻译所有历史静态页面；
- 建立基础语言资源结构，避免继续扩散硬编码中文。

### 首批覆盖

- 应用名称；
- 主导航；
- 仪表盘；
- 设置页核心字段；
- FMO 地址添加 / 编辑；
- 最近通联表头；
- FMO 控制入口；
- 常见连接错误提示。

## 横向能力：远程连接与 DDNS

### V2.0 目标

- 把 V1.x 的临时 DDNS 修复整理成正式用户体验；
- 地址格式合法即可保存，真实连接状态由后续连接流程反馈；
- 区分局域网、DDNS、反向代理、内网穿透、VPN 场景；
- Web 版明确说明 HTTP / HTTPS 入口区别；
- App / 便携版不受公网 HTTPS 页面限制时，提示应与 Web 版区分。

### V2.0 不做

- 不替用户创建 DDNS；
- 不承诺自动打通内网穿透；
- 不保存或上传用户 FMO 访问凭据；
- 不把普通 `ws://` 自动升级为 `wss://`。

## 横向能力：本地收藏

### V2.0 目标

- 本地收藏常用 FMO / 中继 / 服务器；
- 支持备注、排序、最近使用；
- 在仪表盘和车机版中前置收藏入口；
- 与 FMO 固件收藏接口区分，避免误以为一定能写回设备。

### V2.1 预留

- 本地收藏好友；
- 好友活跃提醒；
- 多入口自动检测；
- 远程连接诊断页。

## 旧页面处理

### V2.0 目标

- 精简“更多”页面；
- 弱化或合并旧项目静态页面；
- 致谢、友情链接、说明类页面中有价值的信息合并到“关于”或帮助入口；
- 主导航聚焦当前产品定位：仪表盘、日志、好友、消息、控制、设置。

## 技术前置任务

- 清理全项目 ESLint 既有问题，让 `npm run lint` 重新可作为发布前门禁；
- 为 `src/utils/urlUtils.js` 补充地址规范化测试；
- 梳理 Dashboard 语音、通联、布局逻辑，必要时拆分组件；
- 建立基础 i18n 文案结构；
- 新版布局前确认 V1.x 已修 bug 不被大改覆盖；
- 保持平台抽象边界：Views -> Stores -> Core / Platform。

## 建议实施顺序

1. V1.x 功能 bug 收敛和真机回归；
2. V2.0 版式落地前的组件拆分和 lint 清理；
3. 网页版 / iPad 新仪表盘；
4. 手机竖屏新仪表盘；
5. 车机横屏新仪表盘；
6. 高频入口前置和“更多”页面精简；
7. 基础中英文切换；
8. 本地收藏中继 / 常用入口；
9. 远程连接说明正式化；
10. 三端联测与发布准备。

## 建议拆分会话

- V1.x Bug 修复会话：只处理 `docs/v1.0-tofix.md` 中的功能 bug 和兼容问题；
- V2.0 版式会话：根据 `docs/dashboard-redesign-slices.html` 落地三端布局；
- V2.0 新功能会话：评审收藏、远程连接、愿望墙、好友提醒等功能是否进入 V2.0；
- V2.0 i18n 会话：建立中英文资源和首批页面覆盖；
- 发布工程会话：Win64 签名、Release、SHA256、Android / iOS / Web 发布清单。
