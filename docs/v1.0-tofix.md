## #1 Bug：切换中继后第一个通联仍显示在原来的中继

### 类型

Bug

### 优先级

中高

### 影响平台

- 全平台
- 网页版
- Win64 便携版
- Android
- iOS

### 现象

切换 FMO 中继后，切换后的第一个通联仍然会显示在原来的中继下，而不是显示在新切换到的中继下。

### 影响

该问题会导致通联列表或实时通联状态中的中继归属不准确。用户刚切换中继后看到的第一条通联记录可能被误认为发生在旧中继上，影响值守判断和历史记录可信度。

目前确认所有版本都有该问题，因此更可能是通用业务逻辑或状态同步问题，而不是某个平台的运行环境差异。

### 初步判断

可能与中继状态刷新和通联事件到达之间的时序有关：

- 切换中继成功后，本地当前中继状态未及时更新；
- 第一个通联事件到达时仍使用了旧的 serverInfo / station 信息；
- 中继切换接口成功后没有立即刷新当前中继快照；
- 实时通联事件与中继状态轮询存在竞态；
- 通联记录生成时读取的是旧缓存，而不是切换后的最新中继。

### 期望表现

切换中继成功后，后续发生的通联应显示在新中继下。特别是切换后的第一条通联，不应继续沿用旧中继信息。

### 建议修复方向

- 中继切换成功后立即刷新当前中继信息；
- 在本地先乐观更新当前中继状态，并在后续接口返回后校正；
- 检查通联事件写入 / 展示时使用的 serverInfo 来源；
- 避免第一个通联事件读取到切换前的旧缓存；
- 必要时在切换中继后短时间内强制同步 station:getCurrent。

### 2026-06-05 修复记录

- `switchStationByRelayName()` 增加 `onSwitched` 回调，在 `setCurrentStation()` 成功后立即通知调用方；
- Dashboard 最近通联里的中继快捷切换会立刻更新 `currentStation` 和 `speakingStore.serverInfo`，随后再用 `getCurrentStation()` 返回值校正；
- Dashboard 切换中继后会主动刷新一次 speaking snapshot，减少实时事件继续读取旧中继缓存的窗口；
- 主布局中继列表选择入口也会根据用户选择的 station 立即更新 `speakingStore.serverInfo`，再强制刷新真实 serverInfo；
- 已通过 `npm run typecheck` 和 `npm run build`；完整 `npm run lint` 被项目既有 ESLint 问题阻断，单独检查本次涉及文件无新增错误。

## #2 Bug：部分华为 / 荣耀鸿蒙系统机型打开 Android 版本闪退

### 类型

Bug / Android 兼容性问题 / 已决定不主动适配

### 优先级

不主动修复

### 当前决策

截至 2026-06-05，本问题不再作为 V1.x 主动修复项继续投入。原因：

- 已收集案例集中在华为 / 荣耀老机型升级 HarmonyOS 4.0 后的兼容层；
- 其中 Mate 20 X / Kirin 980 案例底层仍接近 Android 10 / API 29；
- 该类设备 WebView、系统权限、原生插件初始化行为和厂商兼容层差异较大；
- 主动适配成本高，且可能牵制 Android / iOS / Web 主线功能稳定性；
- 当前产品资源优先投入主流 Android、iOS、网页版、Win64 便携版和 V2.0 产品规划。

后续仅保留以下最低限度处理：

- 发布说明中提示 HarmonyOS 4.0 老机型可能存在兼容风险；
- 如用户能提供完整 `adb logcat` 崩溃栈，可再评估是否属于低成本修复；
- 不为 Android 10 / API 29 老鸿蒙兼容层单独牺牲主线能力或大幅降级依赖。

### 已发现平台

- Android 版本安装包
- HarmonyOS 4.0 设备

### 已知机型与系统

- 案例 1
  - 设备：HONOR 20
  - 型号代码：YAL-AL00
  - 系统：HarmonyOS
  - 软件版本：4.0.0.121(C00E120R4P4) GPU Turbo
- 案例 2
  - 设备：HUAWEI Mate 20 X
  - 型号代码：EVR-AL00
  - 系统：HarmonyOS 4.0.0
  - 处理器：Huawei Kirin 980
  - 运行内存：6.0 GB
  - 存储：128 GB，总可用约 16.65 GB
  - 屏幕：2244 x 1080
  - 内核版本：4.14.116，HarmonyOS@localhost #1，Wed Jan 24 00:48:37 CST 2024
  - 备注：该机型鸿蒙 4.0 的兼容层本质仍接近 Android 10 / API 29，未升级到 Android 11/12 底层。

### 目前观察到的共同特征

- 都属于华为 / 荣耀老机型升级 HarmonyOS 4.0 后出现启动闪退；
- 至少一个新增案例属于 Kirin 980 / Mate20 系列，底层兼容层仍是 Android 10；
- 问题可能集中在较旧 Android API、厂商定制 WebView、Capacitor 原生插件初始化或启动权限行为差异上；
- 后续收集案例时需要特别记录机型、型号代码、HarmonyOS 版本、Android API 等级、WebView 版本和是否为 Kirin 980 / 旧旗舰平台。

### 现象

部分华为 / 荣耀机型，尤其是使用鸿蒙系统的手机，打开 Android 版本应用时会闪退。

### 影响

该问题会导致受影响用户无法进入应用，属于启动阻断类问题。由于华为 / 荣耀设备用户量较大，兼容性影响需要优先排查。

### 初步判断

可能原因包括：

- HarmonyOS WebView 与当前 Capacitor / WebView 初始化存在兼容性问题；
- 启动阶段某个 Android 原生插件在该系统上抛出异常；
- 权限、存储、定位或语音相关能力在鸿蒙环境下行为不同；
- WebView 内核版本较旧或厂商定制导致部分前端 API 异常；
- Android 10 / API 29 兼容层对当前 Capacitor、插件或前端构建产物的支持不完整；
- Android 目标 SDK、混淆、原生依赖或启动 Activity 配置与该系统存在兼容问题。

### 需要补充的信息

- 闪退发生在点击图标后立刻退出，还是出现启动页 / 白屏后退出；
- 是否首次安装后必现，还是偶发；
- 是否授予权限后才闪退；
- 是否清除应用数据后仍然闪退；
- 设备实际 Android API 等级，可通过 `adb shell getprop ro.build.version.sdk` 获取；
- 系统 WebView 版本，或是否可以在应用市场 / 系统组件中更新 WebView；
- 通过 Android Studio、`adb logcat` 或应用诊断日志获取崩溃堆栈。

### 建议排查方向

- 连接该设备抓取 `adb logcat`，重点查看 `FATAL EXCEPTION`、`Capacitor`、`WebView`、`FmoEventsPlugin`、`TTS`、`SQLite`、`Filesystem` 等关键词；
- 检查启动时是否过早初始化语音播报、定位、文件系统、事件插件等原生能力；
- 尝试制作一个关闭部分原生插件初始化的测试包，逐项排除；
- 确认设备 Android API 等级、WebView 版本和是否可更新系统 WebView；
- 针对 Android 10 / API 29 设备单独验证启动流程，确认是否存在较新系统 API、权限或 WebView 特性误用；
- 如为 WebView 兼容问题，考虑在启动阶段增加更保守的降级逻辑或错误捕获；
- 如为权限 / 原生插件问题，避免应用启动时因单个能力失败导致整体崩溃。

## #3 Bug：Android 通联日志页通联次数徽标压住呼号文字

### 类型

Bug / 移动端布局问题

### 优先级

中

### 已发现平台

- Android 版本

### 位置

- 通联日志页面
- `Logs` 页面列表
- 对方呼号列

### 现象

在 Android 版本的通联日志页面中，对方呼号后显示的通联次数徽标会压住呼号或下方网格 / 地址文字。

从反馈截图看，类似 `BH1JSS1` 这类较长呼号显示在“对方呼号”列时，通联次数标记与呼号主体或下一行内容发生重叠，影响阅读。

### 影响

该问题会降低移动端通联日志的可读性。用户在手机上查看历史通联时，可能无法清楚区分呼号、通联次数和网格 / 地址信息。

### 初步判断

更像是移动端表格列宽和徽标定位方式不适配：

- 呼号文字较长时没有为通联次数徽标预留空间；
- 通联次数徽标可能使用了绝对定位或紧贴 inline 内容；
- Android WebView 字体渲染、字号或行高与桌面浏览器不同；
- 表格列宽固定，移动端横屏 / 竖屏旋转后内容挤压；
- 呼号、徽标、网格地址共用同一行高，导致垂直空间不足。

### 期望表现

通联次数徽标不应遮挡呼号、网格或地址文字。移动端应保持呼号清晰可读，次数标记可以跟随呼号换行或作为独立小徽标显示。

### 建议修复方向

- 调整 Logs 页面呼号单元格布局，改为 `inline-flex` 或分层块级布局；
- 为呼号和次数徽标增加明确间距，避免重叠；
- 移动端窄屏下允许次数徽标换到呼号后方或下一行；
- 检查 `.contact-count` 在 `LogDataTable.vue` 中的样式，避免绝对定位压住文字；
- 为 Android / 小屏幕增加专门的 `line-height`、`gap` 和 `flex-wrap` 规则；
- 在桌面、移动端竖屏和横屏分别验证长呼号显示效果。

### 2026-06-05 修复记录

- `LogDataTable.vue` 的呼号主行改为可换行 flex 布局；
- 呼号文字由固定宽度改为最小宽度 + 可断行，避免长呼号挤压次数徽标；
- 通联次数改为独立小徽标样式，并与呼号保持明确间距；
- 小屏幕下放宽呼号列和网格 / 地址换行，降低 Android WebView 字体差异导致的重叠概率；
- 已通过 `npm run typecheck` 和 `npm run build`；完整 `npm run lint` 被项目既有 ESLint 问题阻断，单独检查本次涉及文件无新增错误。

## #4 问题：Win64 便携版未签名，容易被杀毒软件删除或拦截

### 类型

发布工程问题 / Windows 安全信誉问题

### 优先级

中高

### 已发现平台

- Win64 便携版 `.exe`
- 可能也影响 `.zip` 解压后的启动脚本或内置运行文件

### 现象

此前发布的 PC 便携版没有代码签名。部分 Windows 环境或第三方杀毒软件会把便携版启动器识别为未知来源程序，出现拦截、隔离、删除或运行前强警告。

### 影响

普通用户可能无法下载、解压或启动 Win64 便携版，也可能误以为软件有安全风险。该问题会显著影响 PC 便携版的可信度和传播。

### 初步判断

Windows 和杀毒软件对以下组合较敏感：

- 未签名 `.exe`；
- 自解压或释放文件到本地目录；
- 启动内置 Node.js 本地服务；
- 自动打开浏览器并监听局域网端口；
- 发布包下载量较小，缺少 SmartScreen / 杀毒厂商信誉积累；
- 可执行文件由脚本或打包工具生成，缺少稳定发行者身份。

### 期望表现

Win64 便携版应尽量减少误报和误删。用户下载后可以正常运行，Windows 或杀毒软件即使提示，也应显示明确的发行者信息，而不是未知发布者。

### 建议解决方向

- 中长期方案：购买并使用 Windows 代码签名证书，对 `.exe` 启动器签名；
- 如果预算允许，优先评估 EV Code Signing 证书，可更快建立 SmartScreen 信誉，但成本和硬件介质要求更高；
- 普通 OV Code Signing 证书也可以显示发布者身份，但 SmartScreen 信誉需要随下载量和时间逐步积累；
- 发布时同时提供 SHA256 校验值，方便用户核对下载文件完整性；
- 在 GitHub Release、README 和便携版说明中解释：软件会启动本地 Web 服务并打开浏览器，属于预期行为；
- 尽量减少启动器行为的“安装器”特征，不静默写入系统目录、不修改注册表、不添加开机启动；
- 检查打包工具是否容易触发误报，必要时改用更常见、更透明的打包方式；
- 对发布产物提交 Microsoft Defender、360、火绒等误报申诉，逐步降低误杀率；
- 对 `.zip` 版本保留透明文件结构，作为杀软拦截 `.exe` 时的备用下载方案；
- 证书私钥必须只保存在本地安全环境或硬件介质中，不进入仓库和自动化日志。

### 短期可执行方案

## #5 临时修复：DDNS 远程地址无法添加

### 类型

Bug / 地址校验问题 / 临时网页版修复

### 优先级

中高

### 已发现平台

- VPS 网页版
- 本地开发网页版
- iOS 版本

### 当前同步范围

- “临时修改测试”会话中先在网页版验证；
- “打包 iOS 版本”会话中已把同一套 DDNS 地址规范化与保存策略同步到 iOS 当前代码；
- Android / Win64 后续如统一整理，应复用同一套 `urlUtils` 规则，避免各平台再次分叉。

### 现象

用户使用 DDNS 或远程域名连接 FMO 时，实际远程地址可以访问，但在设置页添加 FMO 地址时会失败，无法保存到地址列表。

### 影响

使用公网 DDNS、反向代理、内网穿透或带端口域名的用户，可能无法在网页版中添加自己的 FMO 地址，导致后续实时仪表盘、同步、备份和中继控制等功能无法使用该远程地址。

### 初步判断

问题主要来自两处限制：

- 域名格式校验过窄，对部分 DDNS 常见域名不友好；
- 添加 / 编辑地址前必须先通过 WebSocket 探测，DDNS、反向代理、公网 HTTPS 页面访问 `ws://` 地址或网络握手较慢时容易被误判为不可用。

### 本次临时处理

本次仅针对 VPS 网页版做临时修复测试：

- 放宽 FMO 地址域名校验，支持常见 DDNS 域名、短标签域名和带端口地址；
- 地址输入支持粘贴完整 URL，并规范化为主机地址；
- 添加 / 编辑地址时只校验 IP / 域名 / 端口格式，不再用前置 WebSocket 探测结果阻止保存；
- 不再自动把 `ws://` 猜测升级为 `wss://`。实测普通 DDNS 端口通常只提供 plain WebSocket，错误升级会导致 `wss://host:port/ws` 连接失败；
- 不在前端提前阻止 `ws://` 连接。部分浏览器或用户站点设置可能允许不安全内容，实际以 WebSocket 连接尝试结果为准；
- 如果 HTTPS 网页版连接普通 `ws://` 失败，再提示浏览器安全限制；普通 `ws://` 设备优先使用 `http://fmo.bh1jss.net/`、localhost 或 App/便携版访问；
- VPS Nginx 临时开放 `http://fmo.bh1jss.net/` 作为普通 `ws://` 兼容入口；`https://fmo.bh1jss.net/` 继续用于支持 `wss://` 的场景；
- 设置页添加地址不再直接暴露 `ws://` / `wss://` 协议选择，临时改为用户可理解的 `本地IP / 局域网` 和 `DDNS动态域名远程` 两类；背后均按普通 FMO `ws://` 地址保存；
- 选择 `DDNS动态域名远程` 时地址输入框默认留空，并直接提示用户关闭浏览器设置中的“一律使用安全连接”，确认地址栏完整输入 `http://fmo.bh1jss.net/`；
- WebSocket 构造阶段如果被 HTTPS 页面安全策略拦截，临时改为显示中文说明，引导用户改用 HTTP 入口、本地版或 App；
- 保存后的用户信息获取和实际连接仍按原逻辑尽力尝试。

### 当前临时状态记录

截至 2026-05-26，本问题的临时结论如下：

- FMO 本身支持普通 `ws://` 协议地址，Android 版已验证过“动态域名 + 端口”形式可用；
- Win64 便携版、本地开发版和 Android / iOS App 不从公网 HTTPS 页面加载，通常不会遇到“HTTPS 页面禁止连接 `ws://`”这条浏览器限制；
- VPS HTTPS 网页版访问普通 `ws://` 动态域名时，可能被浏览器安全策略阻止；但不同浏览器和站点权限设置表现不同，不应由前端提前一刀切拦截；
- 不应在前端自动把用户选择的 `ws://` 升级为 `wss://`，因为多数普通 DDNS 端口没有 TLS WebSocket；
- 目前 VPS 同时保留两个入口：
  - `http://fmo.bh1jss.net/`：给普通 `ws://` 动态域名 + 端口使用；
  - `https://fmo.bh1jss.net/`：给已配置 `wss://` 的地址使用；
- 仍存在用户浏览器自动升级 HTTPS 的风险。如果浏览器强制把 HTTP 入口升级到 HTTPS，普通 `ws://` 地址仍会不可用；
- 后续正式版本需要把入口说明、协议选择提示和错误文案整理清楚，避免用户误以为“动态域名不可用”。

### 后续正式修复方向

- 在后续版本中把该修复同步到 Win64、Android、iOS 等发行形态；
- 区分“地址格式错误”和“当前网络暂时连接失败”两种提示；
- 可考虑保存地址后显示连接状态，而不是在保存前强制阻断；
- 对 HTTPS 网页连接 `ws://`、`wss://`、反向代理路径、端口转发等场景增加更清楚的用户提示；
- README、设置页和发布说明中补充公网网页版 HTTP / HTTPS 入口区别；
- 评估是否新增一个专用 HTTP 兼容域名，例如 `http://ws.fmo.bh1jss.net/`，专门服务普通 `ws://` 设备；
- 补充地址规范化与校验测试用例，覆盖 DDNS、端口、`/ws` 路径、完整 URL 和非法地址。

### 2026-06-01 汇合记录

来自“临时修改测试”会话的网页版结论与“打包 iOS 版本”会话的 iOS 修复已经合并为同一方向：

- 地址格式合法即可保存，不再因为保存前一次 WebSocket 探测失败而拦截；
- 支持粘贴完整 URL，例如 `http://xxx.ddns.net:40088/ws`、`ws://xxx.ddns.net:40088/events`；
- 支持中文全角冒号，例如 `xxx.ddns.net：40088`；
- 普通裸域名、`http://`、`ws://` 默认走 `ws`，不自动错误升级为 `wss`；
- 用户明确输入 `https://` 或 `wss://` 时保留为 `wss`；
- 切换主 FMO 地址时不再因为远程 DDNS 握手慢或偶发超时就拒绝切换，真实连接失败交给仪表盘、同步和消息连接流程继续反馈；
- `FmoApiClient` 的 WebSocket 构造统一走 `buildWebSocketUrl()`，避免 `/ws/ws`、`/events/ws`、路径残留等问题；
- 当前验证样例包括：
  - `example.ddns.net:40088` -> `ws://example.ddns.net:40088/ws`
  - `http://example.ddns.net:40088/ws` -> `ws://example.ddns.net:40088/ws`
  - `https://secure.example.com/fmo/ws?x=1` -> `wss://secure.example.com/ws`
  - `ws://abc_def.example.net：18080/events` -> `ws://abc_def.example.net:18080/ws`
  - `fmo.local` -> `ws://fmo.local/ws`
