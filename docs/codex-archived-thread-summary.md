## 项目来龙去脉

本项目最初基于原作者 BH5HSJ 的 FmoLogs 项目进行增强，目标逐步从“日志查看器”转为“以仪表盘为核心的 FMO 网页工具”，重点服务业余无线电 FMO 设备的日常通联观察、服务器切换、日志查看和本地化使用。

原始需求从以下几点开始：

- 在通联卡片中给呼号增加 QRZ 查询链接。
- 在本地搭建完整 FmoLogs 测试环境。
- 通过 FMO API 实现简单控制，尤其是切换中继。
- 在日志列表和详情页中，让中继名称可点击并切换到对应中继。
- 按 MIT 协议规范 fork、分支、PR 和文档。

后来项目方向逐步演进为独立仓库 `FMO-Dashboard`，中文名为“FMO仪表盘”，保留对原 FmoLogs 项目和贡献者的致谢。

## 已形成的主要功能

- 仪表盘首页：突出当前或最近发言呼号。
- 当前中继显示：顶部显示正在使用的中继名称。
- 最近通联列表：显示最近通联呼号、时间、QTH、留言、模式、中继等信息。
- 最近呼号去重：同一呼号多次出现时保留最新记录。
- QTH 显示：根据梅登海德网格或经纬度显示位置，后来收敛到省、市、区级别。
- 方位和距离：以用户位置为基准显示对方相对方位、距离和方位盘。
- FMO 中继切换：支持读取当前中继、上一/下一中继、列表选择中继。
- 日志页中继跳转：日志列表和详情里的中继名称可以触发切换。
- 收藏显示：当前固件未开放添加收藏接口，因此未收藏项以小五星和提示文案表达“添加收藏（功能尚未开放）”。
- 语音播报：围绕新呼号、当日新呼号、十分钟未出现呼号设计播报逻辑，并逐步优化为更清晰的播报模式。
- 自己呼号处理：自己的呼号在列表中标记“您”，并且播报逻辑不播报自己的呼号。
- 关于页：改为“FMO仪表盘”，版本显示、功能说明、致谢名单、赞助二维码等都做了本地化调整。
- Win64 本地便携版：支持打包 zip / exe 形式，便于 Windows 用户解压或运行。
- Android APK：改包名和版本逻辑，避免与原 FmoLogs APK 互相覆盖或降级冲突。
- VPS 部署：部署到公网域名，供用户直接访问并配置自己的本地 FMO 地址。
- 访问统计：讨论并实现过 VPS 访问统计页，用于观察访问量、IP、流量和大致地区。

## 重要产品决策

- 项目定位从“FmoLogs 的一个功能分支”升级为独立项目“FMO仪表盘”。
- 仍保留 MIT 协议要求的版权声明和对原项目作者 BH5HSJ 的致谢。
- 独立仓库更适合后续发布 Win64、Android APK、安装包和文档。
- 仪表盘应作为更核心的入口，优先于传统通联日志。
- 网页部署版适合多人访问，每个用户自行配置自己的 FMO 地址。
- 本地 Win64 / Android 版本不应依赖用户访问 VPS 域名，应尽量自带运行环境。
- HTTPS 对公网部署越来越重要，尤其 Chrome 对本地设备访问和混合内容有安全限制。
- Android 版本需要考虑闪退日志、TTS 兼容性和不同机型布局。

## 语音播报逻辑记录

早期设想：

- 历史日志中从未出现过的新呼号：播报呼号后播放三声提示。
- 当日未通联过的新呼号：播报呼号后播放两声提示。
- 十分钟内未出现过的呼号：只播报呼号。

后续为降低混乱，播报模式收敛为：

- 新呼号提示：只播报呼号和提示音，不播放通联语音。
- 通联播报：播放通联语音。
- 关闭所有播报。

Android 端出现过“只有提示音、不播报人声”的问题，因此后续加入或计划加入：

- NATO 字母解释法播报，例如 `BH1JSS` 播报为 `Bravo Hotel One Juliet Sierra Sierra`。
- 离线语音兜底，避免浏览器或 Android TTS 不稳定导致无声。
- 与网页收听 FMO 通联音频避免互相干扰。

## 部署与发布记录

项目讨论过并执行过这些发布路径：

- GitHub fork 分支向原项目 `develop` 提 PR。
- 后来转为新建独立仓库 `FMO-Dashboard`。
- VPS 部署到自有域名，早期为 `fmolog.bh1jss.net`，后来讨论改短到 `fmo.bh1jss.net`。
- Win64 便携包：zip 与 exe 两种方向。
- Android APK：测试版本从 v0.98 进入 v0.99 系列。

涉及服务器密码、私有登录信息、临时图片路径等内容没有写入本文档。
