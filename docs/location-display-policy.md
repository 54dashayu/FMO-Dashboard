# 通联位置与接入模式

## 显示规则

- 2026-11-11 显示简化：FMO 与历史日志只显示地址；无位置只显示“-”。APRS 使用最近一次合法位置，即使 fresh=false 也可显示，但只标注“APRS 最近位置”，不显示具体上报时间，不表示当前位置。
- FMO 数据包的有效网格与有效经纬度属于同一级本次位置，任一有效就使用本次数据，不查询 APRS。同包两者都有效时保留包内网格作为稳定显示表示；两者均缺失或无效才查最近 APRS。经纬度支持数值型 latitude/longitude 或 lat/lon、lat/lng；不猜测字符串单位、缩放整数或未知嵌套结构。
- 本次位置不被历史日志或 APRS 覆盖。无本次位置时查询 APRS 最近位置；原始上报时间仅保留在数据中，不在列表显示。
- 通联时间是接收时间，不等于 GPS 测量时间；历史日志标为记录时间。
- 反查失败仍显示网格。无位置不制造个人地址，不根据呼号地区推算当前位置。
- APRS 缓存最多五分钟。Web 与 Android WebView 共用只读 HTTP 查询实现；Android 仍需真机验证跨域与网络访问。

## 接入模式（用户提供的约定）

| 标识 | 模式 | APRS 查询 |
|---|---|---|
| M. | M5 (ESP32) | 去掉 M.，保留合法 SSID |
| P. | Passport | 去掉 P.，保留合法 SSID |
| .R | RedDV | 去掉 .R，保留合法 SSID |
| AI- | AI | 不查询个人基础呼号 |

未知修饰不擅自删除。模式是按命名约定推断，不代表已验证实际客户端。基础呼号 APRS 是该呼号最后上报位置，不保证与当前软件所在位置相同。

## 协议核查范围

本地 fmo-companion-m5core/main/event_parser.c 可读取 qso/callsign 的 grid，证明伴侣屏接收链路支持网格，不能证明 M. 发射端主动携带位置。未找到可核验的 Passport、RedDV 位置发送源码或完整实际报文，暂不宣称这两者支持 GPS。后续应按各模式抓取实际 qso/callsign 事件验证字段，再扩展映射。
