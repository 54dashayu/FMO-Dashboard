# 未来软件 TODO

> 本文档用于记录 FMO Dashboard 未来方向、产品想法与长期改进项，不归入任何版本 tofix 清单。

## 产品定位

- 围绕 Ham 用户使用 FMO 的真实场景，持续向“FMO 移动控制台和随身显示屏”演进。
- 优先服务移动端、车载、户外、跨网段远程使用等场景。
- 功能设计以“看得清、连得上、控得动、找得到人”为主线。

## 优先级划分

## 建议纳入 V1.0 改进范围

这一组任务优先级最高，适合作为 V1.0 改进的核心方向。它们主要改变用户打开软件后的第一感受，让 FMO Dashboard 从“数据看板”更明确地转向“FMO 移动控制台和随身显示屏”。

- 仪表盘第一屏信息层级优化。
  - 第一屏优先回答“现在正在发生什么”。
  - 当前通讯、连接状态、可执行操作应比历史统计更突出。
- 当前呼叫 + 上一个呼号展示增强。
  - 当前呼叫作为第一视觉中心。
  - 刚通联的前一个呼号显示同类信息，但字体和视觉权重略低。
  - 解决用户错过当前发言开始时“刚刚是谁”的现场问题。
- 精简“更多”页面和旧项目静态页面。
  - 弱化或移除与当前产品定位关系较弱的页面。
  - 重点评估致谢、友情链接、说明类页面。
  - 有保留价值的信息合并到低层级入口。
- 仪表盘增加高频功能入口。
  - 将远程控制、消息、日志、连接诊断等高频功能前置。
  - 减少移动端用户在“更多”页面中寻找操作的次数。
- 手机竖屏和车机横屏布局优化。
  - 手机竖屏重点保证第一屏信息完整、按钮易触达。
  - 车机横屏应重新组织布局，而不是简单拉宽页面。
  - 横屏优先考虑当前呼叫、上一条呼叫、连接状态和快捷控制并列展示。
- 增加中英文界面切换。
  - 所有页面右上角设置齿轮右侧增加地球图标。
  - 点击后可切换中文 / English。
  - 英文版产品名统一为 “FMO- Dashboard”。
  - 建议在 V1.0 页面结构调整时同步建立基础国际化文案结构。

### P0：低难度，适合优先落地

这些任务主要是页面结构、入口整理和本地 UI 调整，不依赖 FMO 固件作者配合，也不需要新增复杂后端能力。

- 精简“更多”页面入口。
  - 评估删除或弱化原 BH5HSJ 项目中与当前定位关系较弱的页面。
  - 可优先处理：致谢页面、友情链接页面、说明类页面。
  - 对确有保留价值的信息，可合并到“关于”或“帮助”的低层级区域。
- 调整主导航和“更多”页面的信息架构。
  - 主导航更聚焦实际使用。
  - “更多”页面减少信息噪声。
  - 将低频静态内容后移。
- 仪表盘增加高频功能入口。
  - 当前连接状态入口。
  - FMO 远程控制入口。
  - 消息入口。
  - 日志/最近通联入口。
  - 连接诊断入口。
- 优化仪表盘第一屏的信息层级。
  - 第一层：当前正在发生什么。
  - 第二层：用户现在能做什么。
  - 第三层：历史数据和辅助信息。
- 当前通讯展示增强。
  - 当前呼号大字号显示。
  - 当前 FMO / 中继 / 连接状态常驻显示。
  - 刚通联的前一个呼号也显示同类信息，字体和权重略低。
- 基础移动端触控优化。
  - 高频按钮更大、更清晰。
  - 减少深层菜单操作。
  - 避免过密信息影响移动端扫读。

### P1：中低难度，需要较多前端整理

这些任务仍以软件自身能力为主，但会涉及较多响应式布局、状态整理和现有页面重组。

- 手机竖屏仪表盘重构。
  - 将第一屏做成“通联现场屏”。
  - 当前呼叫、上一条呼叫、连接状态、快捷操作优先展示。
- 平板与车机横屏布局。
  - 横屏不只是拉宽竖屏，而是重新组织区域。
  - 可考虑左侧显示当前呼叫，右侧显示上一条呼叫、连接状态和快捷控制。
- 车载使用体验优化。
  - 当前通讯信息大字号显示。
  - 关键操作入口保持在第一屏或固定区域。
  - 降低复杂表单在车载场景中的出现频率。
- 初步主题模式。
  - 先做预设主题，而不是完整自定义系统。
  - 可优先提供：默认主题、夜间主题、车机高对比主题。
- 仪表盘快捷操作区。
  - 收藏好友入口。
  - 查看通联历史入口。
  - 发送消息入口。
  - 进入远程控制入口。
- 基础中英文界面切换。
  - 先覆盖主导航、仪表盘、更多页面、设置页等核心页面。
  - 右上角地球图标作为全局语言切换入口。
  - 文案逐步从页面内硬编码迁移到统一语言资源。

### P2：中等难度，需要数据模型和本地状态支持

这些任务需要新增或整理本地数据结构，适合在仪表盘结构稳定之后推进。

- 本地收藏服务器。
  - 收藏常用 FMO / 中继 / 服务器入口。
  - 支持备注、排序、最近使用。
  - 可先只做本地保存。
- 本地收藏好友。
  - 收藏常用呼号。
  - 支持备注、标签、最近活跃时间。
  - 与当前通讯展示联动。
- 好友上线或活跃提醒。
  - 根据现有通联数据判断收藏呼号是否出现。
  - 先做应用内提醒，再考虑系统通知。
- 中继 / 服务器快速切换体验。
  - 将收藏服务器和最近使用服务器前置到仪表盘。
  - 切换后显示结果反馈。
- 远程连接助手基础版。
  - 支持一个 FMO 配置多个入口：局域网、DDNS、内网穿透、VPN 等。
  - 显示当前使用的是本地入口还是远程入口。
  - 记录上次成功连接时间。

### P3：中高难度，需要连接诊断和跨网段体验设计

这些任务不一定需要固件改动，但会涉及网络检测、异常解释、连接策略和更完整的用户引导。

- 多入口自动检测。
  - 检测局域网地址、DDNS 地址、内网穿透地址是否可用。
  - 自动选择当前网络下可用入口。
  - 切换时给出明确提示。
- 远程连接诊断页。
  - 检测域名解析。
  - 检测 HTTP/API 可访问性。
  - 检测 WebSocket 连接。
  - 检测远程控制接口是否可用。
  - 将失败原因翻译成用户能理解的提示。
- 远程连接向导。
  - 我在同一 Wi-Fi 下使用。
  - 我有 DDNS 域名。
  - 我使用内网穿透。
  - 我使用 VPN / Tailscale / ZeroTier。
  - 我不知道怎么选。
- 车机主题完整化。
  - 允许配置字号、密度、按钮尺寸、对比度。
  - 支持横屏固定布局。
  - 确保强光、夜间、车载触控都可用。

### P4：高难度，需要与 FMO 硬件/固件作者沟通

这些任务需要 FMO 固件或协议层提供更明确的能力，软件端可以先预留入口，但不适合单方面承诺完成。

- 从 FMO 网络设置页面读取配置。
  - 需要确认哪些字段可以读取。
  - 需要明确用户授权流程。
  - 需要处理隐私字段脱敏，避免读取 Wi-Fi 密码、token、APRS Passcode 等敏感信息。
- FMO 设备能力接口。
  - 例如设备 ID、当前局域网地址、远程入口、支持的控制能力。
  - 适合未来由固件提供 `/api/device-info` 或 `/api/capabilities` 一类接口。
- 服务器互相拉取。
  - 需要明确 FMO 设备之间如何发现、同步和认证。
  - 软件端可先设计展示和操作入口。
- 远程收藏同步。
  - 服务器收藏、好友收藏是否需要写回设备或云端。
  - 需要定义权限和冲突处理方式。
- 好友关系互相收藏。
  - 需要明确是否存在设备端好友关系、同步机制和隐私边界。
  - 软件端可先做本地好友收藏。
- 设备端好友上线事件。
  - 如果固件能提供结构化事件，软件提醒会更准确。
  - 当前阶段可先用通联数据推断。
- 更标准的当前呼叫状态 API。
  - 当前呼叫、上一条呼叫、持续时间、中继信息最好由 FMO 提供结构化数据。
  - 这会显著提升仪表盘第一屏准确性。

## 推荐选择路径

如果希望按“最容易看到效果”的顺序推进，可考虑：

1. 仪表盘第一屏信息层级优化。
2. 当前呼叫 + 上一个呼号展示增强。
3. 精简“更多”页面和旧项目静态页面。
4. 仪表盘增加高频功能入口。
5. 手机竖屏和车机横屏布局优化。
6. 中英文界面切换基础能力。
7. 本地收藏好友 / 收藏服务器。
8. 好友活跃提醒。
9. 远程连接助手基础版。
10. 多入口自动检测与连接诊断。
11. 与 FMO 作者沟通固件能力接口和服务器互拉能力。

- 车机主题的视觉标准和交互约束。

- 哪些能力可以先做本地版，哪些必须等待 FMO 固件支持。
